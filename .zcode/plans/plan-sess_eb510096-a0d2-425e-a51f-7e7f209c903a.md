# 方案:原项目原地改造升级为 AIHOT 式网站(继续部署 GitHub Pages)

## 总体思路

同一个仓库原地升级:用 Astro 重建 AIHOT 的界面、排版与静态可行的全部功能,构建管线(经 ZCode cron 每日触发)继续充当 AIHOT 架构里"worker+admin"的角色。改造完成后替换现有站点,URL 不变。为保证界面还原度,先克隆 AIHOT 源码到临时参考目录,逐组件移植它的设计(不部署它)。

## 阶段一:数据层扩展(build-data.mjs 构建管线)

1. **事件聚簇**:跨天/跨源的条目按标题相似度归并为"事件"(如某公司发布新机、某里程碑论文的后续报道),生成 events 数据——对应 AIHOT 的 story 归组
2. **热度计算**:热度 = 48h 窗口内独立信源加权数 × 24h 半衰期衰减,每次构建重算;「↑上涨」「新」标记通过保存上次构建的 heat 快照做差值实现(静态站实现 AIHOT 热度算法的等价方案)
3. **搜索**:全站标题/摘要构建中文 bigram 索引 JSON + fuse.js 前端搜索页(零新增原生依赖)
4. **RSS×4**:精选 / 全部 / 全文 / 日报 四路(对齐 AIHOT),另加 llms.txt 与 /agent 说明页
5. 分类体系:把 8 大方向+8 大领域+行业动态映射为 AIHOT 式分类 Tabs(论文进展/硬件平台/行业动态/卫星专题/量子×AI 等)

## 阶段二:界面重建(核心工作量,React→Astro 逐组件移植)

6. 全局框架:桌面左侧 Sidebar + 移动端底部 TabBar + 明暗主题切换,视觉规范对齐 AIHOT(配色变量/字号/间距体系)
7. UI 基建组件:Badge / Kicker / Score(评分徽章)/ SourceAvatar(信源头像)/ Tabs / Menu / Page 容器
8. 页面逐个改造:
   - `/` 首页:品牌栏 +「精选」+分类 Tabs+搜索框 → 当前热点横条 → 按天分组混合信息流(论文+行业动态,"加载更多"客户端分页)
   - `/hot` 热点榜:事件热度排行(涨幅箭头/迷你热度曲线/信源标识/「新」标记)
   - `/events/[id]` 事件页:事件综述 + 关联条目 + 热度走势图
   - `/topics` 主题页:改为 AIHOT 三组式(机构/领域/内容类型)
   - `/daily /weekly /monthly`:改为 AIHOT 报纸式排版(Nameplate 题头/期号圆点/分栏目导语)+ 日报归档
   - `/all` 全部条目流(分类/标签筛选)
   - `/papers/[slug]` 论文详情:条目式重排(中文摘要前置)
   - `/search` 搜索页
   - **保留我们的特色**:/papers 文献库 + 9 个分析面板(AIHOT 没有的学术档案功能,纳入新导航体系)

## 阶段三:验收上线

9. 逐页与 AIHOT 参考界面视觉对比校验
10. 构建→提交→推送 GitHub Pages 替换现有站
11. 更新 PROJECT.md 与 CHANGELOG

## 能力边界(GitHub Pages 静态架构的物理限制,如实说明)

| AIHOT 功能 | 本方案 |
|---|---|
| 精选流/热点榜/事件页/主题页/报表排版/搜索 | ✅ 完整复刻 |
| 事件聚簇+热度算法 | ✅ 构建时等价实现(每日更新) |
| RSS/llms.txt | ✅ 完整复刻 |
| /admin 后台 | ❌ 由 ZCode cron 承担(采集/摘要/入库/建站全自动,现状即此) |
| 实时 API/MCP/运行时分享图 | ❌ 服务器专属,静态站无此层 |
